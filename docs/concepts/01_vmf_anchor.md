## 1. 从头说起：什么是"文本锚点"（软肋1的主角）

### 1.1 先理解 CLIP 在做什么

想象你有一个翻译机，把**任何一句话**翻译成一串数字（比如 768 个数字，就是"768 维向量"）。
这串数字代表这句话的"含义"。含义越接近的句子，翻译出来的数字越相似。

这个翻译机就是 **CLIP 的文本编码器**。

```
输入（句子）                          输出（768 个数字）
"这是一把椅子"         翻译机         [0.12, -0.34, 0.98, ...]
"a photo of a chair"  -------->      [0.11, -0.33, 0.97, ...]  <- 含义相近，数字相近

"这是一只狗"                          [-0.71, 0.52, -0.12, ...]  <- 含义不同，数字很不同
```

### 1.2 什么是"文本锚点"

对于每一个物体类别（比如"椅子"），我们想找到一串"代表这类物体含义"的数字。
这串数字就叫做这个类别的**文本锚点**（text anchor）。

它的用途：当测试时来了一个3D点云，我们把点云也变成一串数字，然后看它和哪个类别的文本锚点最像，就认为这个点云是那类物体。

### 1.3 怎么得到文本锚点

现有做法（Point-Cache 用的）：

```
步骤1：准备 64 句模板句子，把类名填进去：
       "a photo of a chair"
       "a chair in the scene"
       "a point cloud of a chair"
       ... 共64句

步骤2：用 CLIP 翻译这64句话，得到64串数字

步骤3：把这64串数字算术平均，得到1串数字
       （就是把64个数字各自加起来，除以64）

步骤4：把这1串数字"归一化"（使它的长度变为1）

结果：这就是"椅子"类别的文本锚点
```

## 2. 软肋1是什么意思

`00_overview.md` 里说的**软肋1**：

> 文本锚点不够准：算术平均忽略"特征住在球面上"这个事实

这句话有两个陌生概念：**球面**和**算术平均的问题**。下面分别解释。

---

## 3. 球面是什么意思（"特征住在球面上"）

### 3.1 先理解"归一化"

上面步骤4里提到"归一化"。这个操作的效果是：
**把向量的长度（L2 范数）强制变成 1**，只保留方向，丢掉长度信息。

用一个简单例子：

```
原始向量：[3, 4]，长度 = 5（勾股定理：根号(3²+4²)=5）

归一化后：[3/5, 4/5] = [0.6, 0.8]，长度 = 1（根号(0.6²+0.8²)=1）

归一化 = 除以自己的长度
```

### 3.2 "长度为1的向量"住在球面上

在 2D 平面里，所有长度为 1 的向量，它们的端点构成一个圆（单位圆）。

```
(-1,0) ----O---- (1,0)      O是圆心（原点）
        （圆弧）
         (0,1)
          ↑
          这些向量的端点全在圆上
```

在 3D 空间里，所有长度为 1 的向量，端点构成一个球的表面（单位球面）。

在 768 维空间里，同样的道理——所有归一化后的向量，端点都在一个 768 维"超球面"的表面上。

**所以"特征住在球面上"的意思是**：
CLIP 编码后做了归一化，所以所有文本特征向量的长度都是1，都"住"在这个高维球的表面。

### 3.3 为什么这让算术平均出问题

在平面（直线）上，两点的中点就是算术平均，没问题。

但在球面上，两点的算术平均会掉到球面内部，不在球面上了：

```
北极点 N = (0, 0, 1)
南极点 S = (0, 0, -1)

算术平均 = (0, 0, 0) = 球心！

但球心不在球面上，它是"没有方向"的零向量，毫无意义。
```

这在 768 维上同样成立：多个文本特征直接加起来再除以 N，
结果会"往球心方向偏"，偏离球面上真正有意义的位置。

**类比**：用地图上的经纬度坐标算平均，会得出错误的地理位置。
比如北京（116°E, 40°N）和洛杉矶（118°W, 34°N）经度算术平均是 1°E，
但真正的地理中点在北大西洋某处，根本不是经度1°E的那个地方。

## 4. vMF 是什么

vMF = von Mises-Fisher 分布，这是两个德国数学家的姓氏拼在一起的名字。

**最简单的理解**：vMF 是**球面上的"高斯分布"**。

### 4.1 先回顾高斯分布

你可能知道高斯分布（正态分布），它描述"围绕某个平均值的随机波动"：

```
例子：一个工厂生产的螺丝长度服从高斯分布
  平均长度 mu = 10mm
  标准差 sigma = 0.1mm（描述波动大小）
  
  大部分螺丝在 9.9mm ~ 10.1mm 之间
  离 10mm 越远，出现概率越小
```

高斯分布描述的是在"直线/平面/普通空间"里的随机性。

### 4.2 vMF 描述的是球面上的随机性

如果随机性发生在球面上（比如：方向的随机波动），就用 vMF：

```
例子：一群人站在球的表面，各自朝着一个随机方向
  平均方向 mu = 朝北（单位向量）
  集中度 kappa：
    kappa 小 -> 大家方向很分散，朝四面八方
    kappa 大 -> 大家方向很集中，都差不多朝北

vMF 就是描述这种"有中心方向、有分散程度"的球面随机性
```

### 4.3 为什么要用 vMF 描述文本特征

因为文本特征就住在球面上（上面解释过了），所以描述它们的"分布"理应用 vMF 而非高斯。

对于"椅子"类别的文字描述：
- 它们被 CLIP 编码后都在球面上某一小片区域
- 这一小片区域可以用 vMF 来描述：有个中心方向 mu，有个集中度 kappa
- **我们的目标**：找到这个 mu，它就是最准确的"椅子"文本锚点

## 5. MAP 是什么

MAP = Maximum A Posteriori，读作"最大后验估计"。

### 5.1 先理解两种信息来源

当你要做一个判断时，你通常有两种信息来源：

```
信息来源1：你亲眼看到的数据（观测值）
信息来源2：你事先已经知道的知识（先验知识）
```

**例子**：你是医生，要判断病人是否得了某种病

```
先验知识：这种病在人群中的患病率是 1%
           （你还没看这个病人之前就知道的）

观测数据：这个病人的化验单结果
           （你现在看到的）

判断方式：
  纯靠先验 -> 说他没病（因为患病率只有1%）
  纯靠化验单 -> 如果化验阳性就说有病（但化验有误差）
  MAP = 两者结合，综合判断，得到最合理的答案
```

### 5.2 MAP 在 vMF 锚点里的作用

我们有两种信息来估计"椅子"类的真实文本锚点：

```
信息来源1（观测值）：
  用 DeepSeek 生成的 40 句"椅子"的描述
  → 编码成 40 个向量，算出它们的方向均值 m_c

信息来源2（先验知识）：
  Point-Cache 现有的64个模板得到的锚点 z_template
  → 这是我们"已知的"比较靠谱的估计
  → 先验强度 kappa_0 = 5.0（人为设定）
```

MAP 闭式解（结合两者的公式）：

```
最终锚点 a_c = normalize( kappa_hat × m_c  +  kappa_0 × z_template )

含义：
  kappa_hat × m_c   ← 来自40句新描述的贡献（数据多且一致，kappa_hat大）
  kappa_0 × z_template ← 来自先验锚点的贡献（固定权重5.0）

  kappa_hat 是从数据自动估计出来的：
    如果40句描述方向非常一致 → kappa_hat 很大 → 数据贡献大
    如果40句描述方向散乱     → kappa_hat 很小 → 先验贡献大
```

### 5.3 和简单平均的区别

```
简单平均：
  锚点 = normalize(m_c)
  只用新数据，完全不管先验，数据少或散乱时很不稳

MAP：
  锚点 = normalize( kappa_hat × m_c + kappa_0 × z_template )
  新数据和先验都用，数据质量自动决定各自权重
```

## 6. 把上面四个概念串起来

现在我们可以重新解释**软肋1**：

```
Point-Cache 的"软肋1"：

  1. Point-Cache 用"模板平均"得到文本锚点
  2. 这个平均是算术平均，发生在球面上（因为向量都被归一化了）
  3. 算术平均在球面上会向内偏移，得到的锚点位置不准确
  4. 而且它对"几十个模板的描述"一律等权重，
     不能区分"描述一致"和"描述散乱"两种情况

MCP-3D 的修复：

  1. 用 vMF 分布描述文本特征（适合球面）
  2. 用 MAP 估计（结合新数据 + 先验），自动权重
  3. 结果：得到更准确的文本锚点 a_c
```

**这就是软肋1的完整含义**。

## 8. 常见问题

**Q: 为什么要用 DeepSeek 生成40句，而不是直接用 Point-Cache 的64个模板？**

```
A: 64个模板是固定句式，只是把类名填进去，描述很机械。
   DeepSeek 可以生成更丰富、更自然的描述，
   比如"椅子"→"一种有四条腿的座具，通常有靠背"→更接近实际含义。
   40句多样的真实描述，能得到更准确的 vMF 方向估计。
```

**Q: MAP 和 MLE 有什么区别？**

```
A: MLE（最大似然估计）= 只看数据，不管先验
   MAP（最大后验估计）= 数据 + 先验，加权结合
   
   数据很多时，MAP 接近 MLE（先验影响小）
   数据很少时，MAP 偏向先验（先验提供稳定性）
```

**Q: kappa_0 = 5.0 这个先验强度是怎么定的？**

```
A: 是人为设定的超参数，在 W3 阶段做 mini-experiment 扫一遍
   {1.0, 3.0, 5.0, 10.0} 取最优值。
   暂时默认 5.0，这是经验值（参考 2D 上类似工作的设定）。
```
