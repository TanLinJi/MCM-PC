MCP 三缓存机制：Multi-Cache 的灵魂

读完应该掌握：
  1. MCP 为什么要分三个 cache（而不是一个）
  2. entropy / align / negative 三种 cache 各存什么样本、怎么协同
  3. MCP→3D 的关键差异在哪里

这是理解 MCM-PC 主贡献 C1（Multi-Cache Matrix）的前置课。读完后你会知道你论文核心机制具体怎么设计。

1. 一句话定位

MCP 的核心 insight：不同性质的样本对 cache 有不同的价值，应该分开存。单 cache + 单筛选规则 = 信息缺失。

具体来说 MCP 把测试流里看到的样本分三种：

样本性质 直觉描述 用哪个 cache 存
一眼能认对 模型很确定属于哪类，entropy 极低 entropy cache
离类中心很近 不仅置信，而且「长得像类的标准样」 align cache ⭐
模棱两可 在 A 类和 B 类边界，但能给反向信息 negative cache

这三种各自筛、各自存、各自参与最终预测。下面逐个讲清楚。

2. 具体场景：为什么不能只用一个 cache

假设有一个 5 类分类问题（chair / table / car / bike / plane），test stream 一个一个来 1000 个样本。 你只能 每类存 K=3 shot（总共 15 个槽位）。模型对每个样本会给：

  • 一个预测 label ŷ
  • 一个 entropy 值（越低越确定）

问题：该把哪些样本存进 cache？

2.1 朴素方案（Tip-Adapter / TDA / Point-Cache 都这么做）

朴素策略 按 entropy 排序，每类存最低的 3 个。

代码来自 MCP 原版（MCP/mcp_runner.py:31-42）：

def update_cache(cache, pred, features_loss, shot_capacity, include_prob_map=False):
    item = features_loss if not include_prob_map else features_loss[:2] + [features_loss[2]]
    if pred in cache:
        if len(cache[pred]) < shot_capacity:
            cache[pred].append(item)
        elif features_loss[1] < cache[pred][-1][1]:    # 新样本 entropy 比最差的低
            cache[pred][-1] = item                       # 替换最差的
        cache[pred] = sorted(cache[pred], key=operator.itemgetter(1))
    else:
        cache[pred] = [item]
⚠ 缺点 cache 里都是「一眼能认对」的样本。当来一个 长得有点像 chair 又有点像 sofa 的边缘样本时， cache 里清一色标准 chair 没法帮上忙——所有「边缘样本」从 cache 拿到的相似度都很低，几乎没有区分度。

2.2 MCP 的方案

✓ MCP 策略 不只看 entropy。同时还看 离类中心的距离 和 是否在决策边界。 三种筛选规则 → 三个 cache。

下面三节分别讲清楚三个 cache 怎么筛、怎么用。

3. Cache 1：Entropy Cache（高置信库）

📘 Entropy Cache

存什么

每类 entropy 最低的 K=3 个样本的 feature 向量。

来源 = baseline 预测出的伪标签 ŷ，并且 entropy 排序最靠前。

怎么用

推理时计算 query 到 cache 里每个样本的 cosine 相似度，加权得到 cache logits（Tip-Adapter kernel）：

cache_logits = α · exp(−β · (1 − A)) · Vone-hot

其中：

  • A ∈ R1×NK：query 与 cache 样本的相似度矩阵（NK = 类数 × shot 数）
  • V ∈ RNK×N：one-hot label 矩阵
  • α, β：超参（α 控制 cache 整体权重，β 控制相似度衰减锐度）

最终预测：

logits = clip_logits (text-image) + α · cache_logits (cache 投票)
🎯 角色比喻：像班级里的学霸代表。 你不确定一个新同学是哪个班的，问几个学霸代表（很确定属于哪班的样本），它们投票决定。

问题

学霸代表都长得很「标准」。遇到一个长相古怪的新同学（戴口罩 + 换了发型），它们认不出。 → 引出 Cache 2: Align。

4. Cache 2：Align Cache（向心库）⭐ MCP 的核心创新

📗 Align Cache

关键问题：entropy 低 ≠ 离类中心近

考虑这个场景：

edge sample 失败案例
  • 类 chair 在特征空间聚成一团，中心是 c_chair
  • 某样本 X 的 feature 在 chair 团的边缘：
    • 模型预测 chair（置信度高，entropy 低）
    • 但 X 离 c_chair 比较远，更靠近 sofa 团
    • X 实际可能是个 「chair-sofa hybrid」
  • 把 X 存进 cache 的代价：后续来一个真 chair 查询时，X 让 cache 投票偏向 sofa 那一侧
  • → X 是个 cache 的污染源（这就是 D20 P1 发现的 anchor pollution 雏形）

MCP 的解决方案

双重门 在 entropy 之外，再加一个「离类中心距离」的筛选。要进 align cache 必须 两个条件同时满足：
  1. entropy 比 align cache 里最差的样本低
  2. 离类中心的距离也比最差的近

代码逐行

来源：MCP/mcp_runner.py:55-74

def update_align_cache(align_cache, pred, features_loss, shot_capacity,
                       cen, res_text_feat, all_classes, cache_keys=None):
    text_feat = res_text_feat[:, pred]                          # 这一类的文本特征
    class_center = update_class_center(cen, pred, text_feat, cache_keys, all_classes)
    feature = features_loss[0][:1]                              # 新样本 feature
    curr_entropy = features_loss[1]
    feat_dist = torch.norm(feature - class_center)              # 离类中心多远

    if pred not in align_cache:
        align_cache[pred] = []
    if len(align_cache[pred]) < shot_capacity:
        align_cache[pred].append((feature, curr_entropy))       # 没装满直接加
        align_cache[pred].sort(key=lambda x: float(x[1]))
        return

    worst_feat, worst_ent = align_cache[pred][-1]
    if curr_entropy < worst_ent:                                # ① entropy 比最差低
        worst_dist = torch.norm(worst_feat - class_center)
        if feat_dist < worst_dist:                              # ② 距离也更近
            align_cache[pred][-1] = (feature, curr_entropy)
            align_cache[pred].sort(key=lambda x: float(x[1]))

class_center 是什么

不是单纯的「cache 平均」，而是 cache 平均 + 文本中心 加权混合：

ck = cen · (cache 里 k 类的平均 feature) + (1 − cen) · (k 类的 text anchor)

MCP 默认 cen = 0.8：

  • 主要相信视觉 cache（80%）
  • 文本只占 20%（早期 cache 不可靠时回退到文本，cache 多了视觉主导）
→ 3D 迁移注意 3D-text 对齐弱（OpenShape 的 text 锚点没有 CLIP 那么准），如果直接用 cen=0.8， text 提供的「向心力」太弱。这里就是为什么我们需要 C3：vMF 文本锚点—— 先通过 paraphrase + vMF MAP 把 text 锚点做准，再用进 class_center。
🎯 角色比喻：像班里的学霸 + 本地中产代表。 不只置信度高（entropy 低），还要「长得像这个班的典型学生」（离中心近）。 这样筛出来的样本，作为「代表样本」质量更高。

5. Cache 3：Negative Cache（边界库）

📕 Negative Cache

关键问题：中等 entropy 样本怎么用

考虑这个场景：

  • 样本 X 的 entropy 中等（不高也不低）
  • 模型预测 X 是 chair，但置信度只有 55%
  • 第二高的 sofa 概率 35%
  • X 在 chair-sofa 决策边界附近
⚠ 两难 这种样本你不敢存进 entropy / align cache（不够确定，会污染）。 但直接扔掉也浪费：X 至少告诉你「这种 feature 既不太像 chair 也不太像 sofa」。

MCP 的解决方案

把这些「中等 entropy」样本单独存进 negative cache，推理时反向使用（减号而不是加号）。

怎么筛（两层 entropy 过滤）

来源：MCP/mcp_runner.py 主循环

if neg_enabled and neg_params['entropy_threshold']['lower'] < prop_entropy < neg_params['entropy_threshold']['upper']:
    # ① 原始 entropy 在 [lower, upper] 比如 (0.4, 0.8)
    neg_logits = 100. * image_features @ clip_weights
    neg_logits += compute_cache_logits(image_features, entro_cache, ...)   # 加 entro_cache 投票
    neg_loss = softmax_entropy(neg_logits)
    neg_entropy = get_entropy(neg_loss, clip_weights)
    neg_preb = int(neg_logits.topk(1, 1, True, True)[1].t()[0])
    if neg_params['entropy_threshold']['lower'] < neg_entropy < neg_params['entropy_threshold']['upper']:
        # ② 加 cache 投票后还在区间里 → 真的是边界样本，不是噪声
        neg_map = neg_logits.softmax(-1)
        update_cache(neg_cache, neg_preb,
                     [image_features, neg_loss, neg_map],
                     neg_params['shot_capacity'], True)

每个样本存：

key image_features（feature 向量）
value prob_map（logits softmax 后的概率分布，不是 one-hot label）
loss 用于排序，保留最差的

怎么用（反向）

推理时从 final logits 里减，不是加：

final_logits -= compute_cache_logits(
    image_features, neg_cache,
    neg_params['alpha'], neg_params['beta'], clip_weights,
    (neg_params['mask_threshold']['lower'], neg_params['mask_threshold']['upper'])
)

关键细节：neg_mask_thresholds 把 prob_map 转成 binary mask：

cache_values = ((cache_values > neg_mask_thresholds[0])
              & (cache_values < neg_mask_thresholds[1])).int8

意思：只把 prob_map 里概率在中等区间（比如 0.03 ~ 0.20）的类标记成 1。

  • 某类概率 > 0.20 → 模型相对确定，不算真的「边界」
  • 某类概率 < 0.03 → 完全无关，也不是边界
  • 0.03 ~ 0.20 → 真正的边界类，给反向信号
🎯 角色比喻：像班里的「边缘案例」档案。 不存「确定不是 chair 的样本」，而是存「对 chair 来说有点像但不太像」的样本。 推理时：query 如果跟 cache 里「既像 chair 又像 sofa」的样本相似，就把 chair 和 sofa 的 logits 都减一点，让真正最像的类突出。
→ 3D 迁移注意 Point-Cache 已经有 neg_cache（机制几乎一样）。MCM-PC 直接复用 Point-Cache 的 neg_cache， 不要重复实现一份（G6 漏洞修补）。

6. 三个 Cache 怎么协同（推理时）

6.1 主公式

final_logits = clip_logits
             + α · entropy_cache_logits(query, entro_cache)
             + α · align_cache_logits(query, align_cache)

目的：让 align cache 算出来的 prototype 反过来更新 entropy cache 的 class_center。 两个 cache 互相增强。

7. MCP++（残差精修）

MCP 本身是无参数的（cache 是状态，不是可学习参数）。MCP++ 在 MCP 之上加了一层轻量级 learnable residual。

7.1 三个 learnable 模块

来源：MCP/mcp_runner.py:179-200

class TextResidue(nn.Module):
    # 在 text anchor 上加 0-init 残差
    def forward(self, x):
        return F.normalize(F.normalize(x, dim=0) + self.residual, dim=0)

class PositiveCacheResidue(nn.Module):
    # 在 cache keys 上加 0-init 残差
    def forward(self, x):
        return F.normalize(x.clone() + self.residual, dim=0)

7.2 优化目标

每个测试样本上跑 1-2 步梯度下降：

loss = entropy_loss
      + λ · img2text_loss (InfoNCE: image cache ↔ text anchor 拉近)
      + γ · pos2neg_loss (pos cache ↔ neg cache 拉开)

7.3 MCP++ 在 3D 里要不要做？

⚠ 决策 default OFF，CVPR 阶段（W21）再考虑。
  • 3D-text 对齐本来就弱（OpenShape contrastive 训练数据少）
  • residual 太多反而把好不容易学的 cache 扰乱
  • AAAI 阶段做 MCP（不带 ++）就够卖一篇

8. MCP（2D）→ MCM-PC（3D）的关键差异

这是把 MCP 翻译到 3D 时必须想清楚的几个点。每一行都是潜在的 bug 源。

维度 MCP (2D) MCM-PC (3D) 怎么处理
encoder CLIP ViT-B/16 OpenShape PointBERT-vitg14 直接换，feature 都是 768 维
augmentation TPT 的 60 个 crop + 平均（select_confident_samples） 3D 没有标准 aug 配方 方案 A：先不做 aug；方案 B：用 Point-Cache 的 hierarchical 5-patch 当 aug 等价物
align_pred 来源 60 个 aug 的平均预测 直接用 single-view 预测 简化，先不做 aug。后期如效果不够再补
class_center 文本部分 clip text embedding（质量好） OpenShape text embedding（质量差） C3 vMF anchor 来救：用 paraphrase 平均 + vMF MAP 增强文本
negative cache MCP 自实现一份 Point-Cache 已经有 neg_cache 不要重复：复用 Point-Cache 的（修补 G6 漏洞）
local 表征 没有（2D single-feature） Point-Cache 自带 hierarchical：patch_centers (5, d) 沿 representation 轴扩展矩阵：global × local
预测 pred 同时给 ent_pred + align_pred（两路） baseline 只给一路 简化为单一 pred，align cache 也用它
residual learning MCP++ 默认 ON 3D-text 弱，先 OFF AAAI 不做；CVPR 阶段 W21 再视效果决定

9.4 上层「Conditional Anchor Source」元机制

来自 D20 P1 探针 D20 发现：仿射类 corruption（scale / rotate / add）下 cache 被 anchor pollution 主导， 替换成训练集 prototype 能拿 +10~13pp oracle 增益； 但 jitter / heavy dropout 下 clean anchor 反而灾难（−25~−63pp）。

把这个发现工程化为 cache 来源选择器，放在矩阵之上：

def select_anchor_source(query_feat, training_prototypes, stream_cache, tau_lo, tau_hi):
    proto_sim = (query_feat @ training_prototypes.T).max()  # query 到最近 prototype
    if proto_sim > tau_hi:
        return 'static'   # E plan: cache 用训练集 prototype 填（防污染）
    elif proto_sim > tau_lo:
        return 'stream'   # 原版: 用流式 cache
    else:
        return 'abstain'  # D plan: 跳过 cache，只用 text logits

这就是 C2 (Corruption-Aware Anchor Source)。它不进矩阵，而是控制矩阵 cache 的来源。
