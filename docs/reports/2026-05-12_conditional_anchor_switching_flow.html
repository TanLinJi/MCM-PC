Conditional Anchor Switching 整体流程图

中文名：有条件的锚点来源切换。目标是在 scale 这类 feature 仍可靠但 cache anchor 容易污染的场景中使用 stable anchor source，同时在 jitter 这类 feature 已明显漂移的场景中避免 clean/source anchor 造成负迁移。clean anchor 是 oracle，labeled source prototype 只能作上界；strict source-free TTA 主线应使用 text / vMF anchors 或高置信测试时证据。

Corrupted point cloud测试时输入的损坏点云，例如 scale_2 或 jitter_3。
→
3D encoderOpenShape / PointBERT，把点云编码成 query feature。
→
Reliability estimator估计当前 feature 是否可靠。候选信号：entropy、max prototype cosine、top1-top2 margin。
→
Anchor source selector根据可靠性选择锚点来源，而不是固定使用一种 cache。
→
Final logits融合 text logits 与被选中的 anchor/cache evidence，输出预测。
Reliable → stable anchor sourcefeature 接近稳定类别锚点。strict source-free 主线使用 text / vMF anchor 或高置信测试时锚点。
Uncertain → stream anchor中间区域暂时保留 Point-Cache 原始测试流 cache，避免过早切换。
Unreliable → abstentionfeature 已明显漂移时，跳过 cache evidence，回退到 text logits 或 baseline-safe 输出。

三个锚点选择是什么意思

选择中文解释什么时候用P1 证据
stable anchor source稳定锚点来源，不被低置信测试流连续污染。clean anchor 是 oracle；source prototype 是上界；text / vMF anchor 才是 strict source-free 主线。query feature 仍可靠，接近某个稳定类别 anchor。scale_2 clean oracle anchor 比 corrupted stream anchor 高 +11.02pp，说明稳定锚点有价值。
stream anchor测试流锚点。Point-Cache 原本的 cache，用测试过程中见过的样本作为参照。可靠性处于中间区间，stable anchor 未必安全，完全 abstain 又可能浪费可用信息。jitter 中 stream statistics 有时比 clean anchor 安全。
abstention弃权。不是不预测，而是不使用 cache/anchor 这条证据。feature 明显不可靠，stable anchor 和 stream anchor 都可能放大错误。jitter_3 clean anchor 比 corrupt anchor 低 -51.18pp，必须有安全出口。

为什么不是只用 entropy

信号含义它回答的问题
entropy预测熵，模型输出分布的不确定性。模型现在是否犹豫？
max prototype cosinequery feature 与最近训练类别 prototype 的余弦相似度。feature 是否还在某个类别附近？
top1-top2 margin最近类别 prototype 与第二近类别 prototype 的相似度差距。最近类别是否足够明确？
scale regime

feature 可靠，stream anchor 易污染。优先验证不被污染的 stable anchor source。

jitter regime

feature 明显漂移，clean/source anchor 可能有害。必须保留 abstention 安全出口。

method goal

不是设计一个永远生效的 anchor，而是设计一个能选择何时信哪类 anchor 的 selector。
