1. 问题定义：3D 点云的 Test-Time Adaptation

训练时
模型见到的是干净数据，例如 ModelNet 的 CAD 点云。
部署 / 评测时
真实挑战是分布偏移；benchmark 用 jitter、dropout、rotate、scale 等人工 corruptions 做可控代理和压力测试。
目标
测试时边推理边适应，但不改参数、不用标签。

论文里要抓住一句话：TTA 不是重新训练模型，而是在测试流中利用当前样本和记忆来修正预测。

2. 为什么 3D 比 2D 更难

3D 点云不只是“图像换个模态”，它多了几何结构。人工构造的旋转、尺度变化、点缺失等 corruption 会直接改变坐标分布，进而影响 3D encoder 的 feature。

2D: pixel layout changes, semantic content often stable
3D: (x, y, z) geometry changes, feature may drift strongly

论文写作锚点

如果 feature 距离在可控几何 corruption stress test 下失灵，那么只依赖 feature cache 的方法会有结构性风险。

这就是 MCP-3D 引入 ICP-CD 的根本动机：直接补一条几何证据链。

3. 现有 SOTA：Point-Cache 的基本机制

Step 1
新点云 X 进入 3D-VLM，得到 feature z。
Step 2
z 与记忆库中每类 anchor feature 比较距离。
Step 3
用高置信预测更新 memory，辅助后续测试样本。

Point-Cache 的强处是简单有效；MCP-3D 的论文不能否定它，而要说明：它在几何 corruption benchmark 下还有可补强的空间。

软肋 1：文本锚点不够准

固定模板做算术平均，忽略 CLIP 类特征位于单位球面这一事实。

对应解法：vMF MAP 文本锚点。把同一类别的多条 prompt 看成球面上的样本，用 vMF 分布估计更合理的类别方向，避免普通平均把 anchor 拉偏。

软肋 2：feature 距离怕几何破坏

旋转、缺失、尺度变化可能把同类点云推到远离原 anchor 的区域。

对应解法：ICP + Chamfer Distance。先用 ICP 对齐两个点云，再用 Chamfer Distance 比较形状差异，为 feature 相似度之外补一条几何证据。

软肋 3：不知道 memory 是否在变坏

测试流更新可能导致记忆库逐渐发散，最后反过来污染预测。

对应解法：compactness diagnosis。定期测量同类 memory 是否仍然聚在一起；如果类内距离变大、紧致性下降，就说明 memory 可能被错误样本污染。

4. MCP-3D 的贡献结构

编号贡献论文角色风险等级
C1ICP-CD 几何距离方法创新，补 feature 失败高：需要实验证明 feature 确实失败
C2紧致性诊断科学发现，解释 memory 何时变坏中：避免标签泄露
C32×3 记忆矩阵工程整合，多证据融合中：必须做 leave-one-out
C4vMF 文本锚点数学严谨化，替代普通均值低：理论依据稳定

注意：boundary memory 不是“负样本库”，而是记录不稳定区域，用来校准过度自信。

6. 项目故事一句话

3D 点云 TTA 有几何扰动、memory 漂移、文本锚点不严谨三个问题；MCP-3D 用 ICP-CD、compactness diagnosis、2×3 memory matrix 和 vMF anchor 形成几何感知的多记忆框架，目标是在 ModelNet-C / ScanObjectNN-C 上稳定超过 Point-Cache。

7. 下一步概念复习顺序

01 vMF Text Anchor

解决“文本类锚点如何更符合球面特征空间”的问题。

02 ICP-CD Geometry Distance

解决“feature 距离失灵时如何引入原始几何证据”的问题。

03 Compactness Diagnosis

解释 memory 什么时候变散，以及如何和性能下降关联。

04 2×3 Memory Matrix

把 confidence、compactness、boundary 与 global/local 组织成最终方法。
