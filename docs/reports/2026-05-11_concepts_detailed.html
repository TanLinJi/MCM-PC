这份讲义的核心问题

Point-Cache 已经是 3D TTA 的强 baseline。MCP-3D 要证明的不是“Point-Cache 错了”，而是：它在 3D 几何扰动、文本锚点、记忆库漂移三个方面还有可解释、可验证、可改进的空间。

00 · 大背景与项目全貌

先把论文问题说清楚：我们做的是 3D 点云 Test-Time Adaptation，不是重新训练模型，也不是监督学习。

训练时

模型主要在干净数据上训练，例如 ModelNet 这类 CAD 点云。训练集分布比较规则，噪声和几何破坏相对少。

部署 / 评测时

真实部署中的核心挑战是分布偏移；ModelNet-C / ScanObjectNN-C 用 jitter、dropout、rotate、scale 等人工 corruption 作为可控 proxy / stress test，导致点云坐标和局部结构改变。

TTA 目标

测试时边预测边适应，但不使用标签、不反向传播更新模型参数，只利用当前测试流和 memory。

写作边界：corruption 不等于现实分布偏移本身

论文里应该把真实世界问题表述为 distribution shift，把 ModelNet-C / ScanObjectNN-C 的 corruption families 表述为“人为构造的可控代理任务”。因此，scale 下的负增益只能说明 Point-Cache 在该 benchmark stress-test family 上存在失败模式，不能直接写成现实世界中所有尺度漂移都会导致同样失败。

推荐写法：real-world distribution shifts motivate robustness evaluation; controlled corruptions such as scale / rotate / jitter are used as diagnostic stress tests.

Point-Cache 的基本逻辑

1
编码
测试样本 X 进入 3D-VLM，得到 feature z。
2
检索
z 与每类 cache anchor 比较 feature 距离。
3
更新
把高置信预测样本写回 memory，服务后续测试样本。

它的优点是简洁有效；MCP-3D 的切入点是：在可控几何 corruption stress tests 中，当 feature space 不可靠时，原系统缺少几何兜底和记忆健康诊断。

软肋 1：文本锚点不够准

Point-Cache 用多 prompt 的普通平均构造类别文本 anchor，但 CLIP / OpenShape 特征是归一化向量，本质上位于单位球面。

对应解法：vMF MAP 文本锚点。

软肋 2：feature 距离怕几何破坏

旋转、尺度变化、缺点等 benchmark corruptions 可能让同类点云在 feature space 中远离，即“feature distance 撒谎”。

对应解法：ICP + Chamfer Distance。

软肋 3：不知道 memory 是否变坏

测试流更新会把模型自己的预测写回 memory；一旦错误样本入库，memory 可能逐渐散开并污染后续预测。

对应解法：compactness diagnosis。

01 · vMF 文本锚点：让类别语义方向更合理

这个概念解决的是“每个类别的文本 anchor 应该怎么估计”。它是低风险但有理论加分的 C4。

什么是文本锚点？

在 CLIP-style 3D-VLM 里，分类常常是比较点云 feature 和文本 feature 的相似度。每个类别都需要一个文本代表方向，例如 `chair_text_anchor`。

预测 = argmax_c sim(z_point, text_anchor_c)

如果 text anchor 偏了，初始 text logits 就会偏，后续 memory 更新也可能被带偏。

Point-Cache 的普通平均

原始做法通常是准备多条 prompt，把它们编码成文本向量，再做算术平均和归一化。

t_1, t_2, ..., t_64 → average → normalize → anchor

严谨说，问题不在于“多 prompt”错了，也不能说归一化均值必然错误；问题在于它只是一个无不确定性、无先验、等权重的点估计。

为什么“球面”很重要？

CLIP / OpenShape 往往会把 feature 归一化，也就是强制向量长度为 1。归一化之后，向量主要表达“方向”，不再表达长度。

||t_i|| = 1, ||z_point|| = 1

所有长度为 1 的向量都在单位球面上。球面上的“中心”应该是方向中心，而不是普通欧氏空间里的坐标平均。

普通均值 + normalize = 球面方向点估计；vMF-MAP = 球面概率模型 + 先验收缩 + 置信度建模。

论文数学论证：不要证明“普通平均必错”，而要证明“普通平均脆弱”

设每条 prompt 的归一化文本特征为 t_i ∈ S^{d-1}。Point-Cache 的类别锚点可以写成：

a_PC = normalize(Σ_i t_i)

如果所有 t_i 都独立来自同一个理想 vMF 分布 vMF(μ, κ)，那么 normalize(Σ_i t_i) 实际上就是 mean direction μ 的最大似然估计（MLE, Maximum Likelihood Estimation）。所以论文里不能说它“数学上错误”。

Point-Cache 的真实弱点
它默认所有 prompt 同质、等权、无噪声，并且只输出一个点估计；当 prompt 存在多语义模式、模板偏差或类名歧义时，它不知道自己的 anchor 是否可靠。
vMF-MAP 的改进点
它显式估计 prompt 集中度 κ，再用先验 anchor 做 Bayesian shrinkage；当新 prompt 方向一致时相信数据，当 prompt 分散时回退到先验。
噪声 prompt 模型：E[t] = (1-ε) A_d(κ) μ_c + ε m_noise 如果 ε > 0，普通均值方向会被 m_noise 拉偏； vMF-MAP: a_MAP = normalize(κ_hat · m_c + κ_0 · a_prior) 当 κ_hat 小时，自动降低 noisy prompt 的影响。

论文里的可靠性主张应写成：“在 noisy / mixed prompt distributions 下，vMF-MAP 是比等权点估计更稳健的球面估计器”，并用 simulation + ablation 支撑，而不是宣称普通平均在所有情况下都不可靠。

vMF 是什么

von Mises-Fisher 分布可以理解成“球面上的高斯分布”，用来描述围绕某个中心方向的随机方向样本。

μ 表示什么

`μ` 是 mean direction，也就是某个类别在文本语义空间里的主方向。我们最终想要的 anchor 就是它。

κ 表示什么

`κ` 是 concentration。κ 大说明 prompt 方向一致；κ 小说明 prompt 分散，应该更依赖先验。

MAP 如何把“新描述”和“先验模板”结合

这里的 MAP 是 Maximum A Posteriori。它不是完全相信新生成的 paraphrase，也不是完全沿用旧模板，而是把两者按可信度加权。

a_c = normalize( κ_hat × m_c + κ_0 × z_template ) m_c: 新生成描述的方向均值 z_template: Point-Cache 原有模板 anchor κ_hat: 从新描述一致性中估计出的集中度 κ_0: 先验强度，默认可从 5.0 起步扫描
如果新描述很一致
κ_hat 大，数据贡献更大，anchor 更偏向新描述提供的语义方向。
如果新描述很散乱
κ_hat 小，先验模板贡献更大，避免 anchor 被噪声描述拉偏。

为什么 vMF 只放在文本侧？

理由文本侧点云侧结论
样本量每类几十条 paraphrase，少而稳定TTA 中 cache 样本更多但可能更脏文本侧更需要参数化分布稳定估计
算力启动时离线计算一次每 batch 都动态更新点云侧频繁拟合 vMF 成本过高
结构信息主要是语义方向包含真实 3D 几何结构点云侧更适合 ICP-CD 和 KNN 经验聚合

对应文档：`docs/concepts/01_vmf_anchor.md`；实现位置计划：`Point-Cache/runners/model_with_mcp3d.py` 中 `compute_vmf_anchor` / `build_vmf_text_anchors`。

02 · ICP-CD 几何距离：当 feature distance 撒谎时补一条几何证据

这是 MCP-3D 的核心高风险贡献 C1。它要证明：在某些可控 3D corruption stress tests 下，feature 距离不可靠，而几何距离能提供互补信号。

feature distance 为什么会失败？

假设两把椅子本来同类，但一把旋转了 90°。理想情况下 encoder 应该旋转不变，二者 feature 相似度仍然高。

理想：cos(z_chair, z_rotated_chair) ≈ 0.95

但如果 encoder 只是“近似不变”，实际可能变成：

失败：cos(z_chair, z_rotated_chair) ≈ 0.50

Point-Cache 的缺口

Point-Cache 主要相信 feature space：feature 近就是同类，feature 远就是异类。一旦 feature space 在可控几何 corruption 下出错，系统没有直接查看 3D 形状的兜底机制。

论文要证明的关键：不是说 feature 没用，而是说 feature 在某些 benchmark corruption families 下会局部失灵。

必须补的实验证据：feature distance 真的会失败吗？

这个不能只靠直觉，必须用 probe experiments 证明。建议把它写成 C1 的前置诊断实验，而不是直接跳到方法。

实验要证明什么指标失败/通过判据
P1 feature invariance probe同一物体经过 rotate / scale / dropout 后，feature 是否仍然接近cosine similarity drop、clean-corrupted rank若同物体 pair 的 cosine 明显下降或 rank 跌出 top-k，说明 feature distance 有局部失败
P5 cross-method negative gainscale 负增益是 hierarchical 特例，还是 cache-family 共性ZS / global cache / hierarchical cache 的 scale 列差异决定论文写“方法共性”还是“hierarchical failure mode”
Feature-vs-geometry ROCfeature distance 和 ICP-CD 谁更能区分同类/异类 pairROC=Receiver Operating Characteristic，AUC=Area Under the Curve若 feature AUC 降而 ICP-CD AUC 稳，C1 成立；若二者都低，C1 需要降级

ICP-CD 的三步流程

1
PCA 主轴预对齐
先把两个点云的主要变化方向对齐，给 ICP 一个好初值。
2
ICP 细对齐
迭代寻找旋转 R 和平移 t，使 source 点云尽量贴合 target 点云。
3
Chamfer Distance
对齐后计算两个点云互相最近邻距离的平均，CD 越小形状越像。
CD(P, Q) = mean_p min_q ||p - q|| + mean_q min_p ||q - p||

理论希望

同类点云即使姿态不同，经过 ICP 对齐后应该形状接近，CD 较小；异类点云即使强行对齐，形状结构仍不同，CD 较大。

核心隐忧

异类但形状相似的对象可能也有小 CD，例如扶手椅 vs 小沙发、无靠背椅 vs 小桌子。这就是 C1 的阻断级风险。

如何解决 C1 的阻断级风险？

C1 不能设计成“只要 ICP-CD 小就相信几何”。正确策略是把 ICP-CD 当作互补证据，并且用门控机制防止相似异类误伤。

1. 跨类 ROC / AUC 先验检查
先测 ICP-CD 对 same-class vs different-class pair 的区分度。若 AUC < 0.7，C1 不能作为主预测模块；若 AUC > 0.85，几何证据站得住。
2. margin gating
不仅看最小 CD，还看 top-1 与 top-2 几何距离的 margin。如果 chair 和 sofa 的 CD 都小，说明几何不确定，应降低 geometry 权重。
3. 多源一致性融合
ICP-CD 只在 feature 不确定或 corruption stress test 暴露 feature failure 时加权增强；最终仍与 text logits、feature cache、boundary calibration 一起决策。
safe_geo_weight = g(AUC_classpair, CD_margin, feature_entropy) if CD_margin small or class-pair AUC low: reduce ω or fallback to feature/text else: use ICP-CD as complementary evidence

这意味着 C1 的安全版本不是“几何替代 feature”，而是“几何在可验证可靠的区域补充 feature”。

feature 距离和几何距离如何融合？

两种距离量纲不同，不能直接相加。计划使用 per-class running statistics 做 z-score，再加权融合。

z_feat = (d_feat - μ_feat_c) / σ_feat_c z_geo = (d_geo - μ_geo_c ) / σ_geo_c d_combined = (1 - ω) × z_feat + ω × z_geo
ω = 0
只用 feature，退化为 Point-Cache 类似逻辑。
ω = 0.5
feature 与 geometry 等权，是初始合理点。
ω = 1
只用几何，风险是相似异类可能混淆。

对应文档：`docs/concepts/02_icp_cd_distance.md`；实现位置计划：`pca_principal_axis_align`、`icp_then_chamfer`、`compute_cell_logits`。

03 · Compactness Diagnosis：给 memory 做体检

紧致性诊断不是直接提高性能的在线模块，而是解释 TTA 成败机制的离线科学分析，对应 contribution C2。

什么是紧致性？

对于某一类 c，如果 memory 中的 anchor 都靠近该类文本锚点，说明它们很“紧”；如果 anchor 分散，说明 memory 可能变脏。

Φ(c) = mean_k || z_k - a_c || Φ 小 → memory 紧致 → 类内方差小 → 决策稳 Φ 大 → memory 松散 → 类内方差大 → 决策不稳

为什么这是“诊断”而不是“方法”？

紧致性测量可能需要真实标签来确认某个 anchor 是否真的属于类 c。因此它不能直接用于无监督 TTA 推理过程。

关键表述：它是离线诊断工具，用于理解模型为什么失败，而不是部署时参与预测的在线模块。

它从 2D MCP 论文继承了什么问题？

2D MCP 发现：memory compactness 与最终精度之间强相关，Pearson r 约为 0.82。MCP-3D 要问的是：这个现象在 3D 点云 TTA 中是否仍然成立？

情况 A：r ≈ 0.82
说明 2D 发现跨模态成立，可写成普适规律。
情况 B：r ≈ 0.5-0.75
说明 3D 中部分成立，可写成 corruption-specific 现象。
情况 C：r < 0.3
说明 C2 失败，需要改写为“3D 与 2D 不同”的反向叙事。

测量流程

1
跑完整 TTA
模型正常预测、正常更新 memory，不用标签参与推理。
2
周期性记录
每 50 步记录 Φ(c) 和窗口精度，形成时间序列。
3
离线分析
计算 Pearson r，画 Φ-accuracy 散点图和跨 corruption 表格。

对应文档：`docs/concepts/03_compactness_diagnosis.md`；计划实现：`Point-Cache/utils/diagnosis.py` 中 `measure_compactness`、`log_phi_vs_acc`、`compute_pearson_r`。

04 · 2×3 Memory Matrix：把多源证据组织成最终方法

这是工程整合贡献 C3。它不是单个 cache，而是按“表征轴 × 功能轴”拆成 6 个格子。

两条轴

表征轴：global / local
global 看整个点云；local 看局部 patch。这个继承自 Point-Cache 的层次记忆。
功能轴：confidence / compactness / boundary
confidence 存高置信样本；compactness 存几何相似样本；boundary 存决策边界附近样本。

2×3 矩阵布局

Global
整个点云
Local
局部 patch
Confidence
global_conf
低 entropy 的整体样本，作为每类标杆。
local_conf
低 entropy 的局部 patch，对遮挡更鲁棒。
Compactness
global_comp
用 ICP-CD 选几何上最像的整体样本。
local_comp
用 patch ICP-CD 选局部几何相似样本。
Boundary
global_bnd
中等 entropy 的模糊整体样本，提供校准信号。
local_bnd
默认关闭，待 ablation 验证是否保留。

最终融合公式：口述版

final_logits = text_logits + positive memory evidence - boundary calibration evidence

其中 positive memory 包括 confidence 和 compactness 格子；boundary 用负号不是“负样本训练”，而是在推理 logits 层面对模糊区域进行校准。

boundary memory 的正确理解

它不是 negative sample。MCP-3D 是 training-free TTA，没有 loss、没有反向传播、没有把特征推远的训练过程。

它是 calibration signal：如果当前查询像 boundary 样本，说明它可能也处于模糊区，应该降低过度自信。

推理时完整流程

1
编码
得到全局 feature、local patch feature，以及离线 vMF text anchors。
2
算格子 logits
每个 memory cell 都输出一组类别 logits。
3
融合预测
text + 正向格子 - boundary 校准，得到 final logits。
4
更新 memory
根据预测和筛选标准，把当前样本写入相应格子。

对应文档：`docs/concepts/04_2x3_memory_matrix.md`；计划实现：`CellConfig`、`MemoryCell`、`MCP3DMemoryMatrix`、`fuse_multi_source_logits`。

新的论文卖点：diagnosis-driven TTA

这个方向可以成为文章的重要卖点：我们不是只堆一个新 cache 模块，而是从根因上分析为什么当前 SOTA 在某些 benchmark corruption 下会出现负增益。

现有方法常见叙事：提出新模块 → 跑 benchmark → 精度提升 MCP-3D 更强叙事：发现负增益 → 诊断 feature/cache/memory 失效机制 → 设计几何感知多记忆修复 → 用 probe + ablation 验证每个机制
可写进 Introduction
“We provide a diagnosis-driven analysis of negative adaptation in cache-based 3D TTA, and use the diagnosis to motivate geometry-aware memory design.”
注意前提
这个卖点需要 P5 / P1 / P2 支撑。没有跨方法和机制实验前，只能写成 hypothesis / preliminary observation，不能写成最终结论。

实验门控：哪些概念必须被验证

概念阶段的最终目标，是知道后续 W2.5/W3-W7 为什么要这样跑。

P1：旋转不变性探针

验证 3D-VLM feature 是否真的在旋转下显著漂移。

阻断风险

如果 cosine 始终 > 0.95，ICP-CD 的必要性下降，C1 需要重新定位。

P2：紧致性相关探针

验证 3D memory compactness 和 accuracy 是否相关。

阻断风险

如果 r < 0.3，C2 不能按原叙事写，需要 pivot。

P5：跨条件几何探针

验证 ICP-CD 在不同 corruption 下是否提供稳定互补信号。

关键补强

它帮助确定 ICP-CD 是 generalizable 贡献，还是只对某些情况有效。
